## Что делаю

### 1. Сохранение состояния каталога (фильтры/поиск/категория)
Переношу состояние главной страницы в URL search-параметры (`?g=man&q=samba&sort=discount&sale=1`). Тогда при возврате со страницы товара TanStack Router восстановит скролл и параметры автоматически. Плюс сохраняю позицию скролла на `sessionStorage`.

### 2. Включаю Lovable Cloud
- Аутентификация: email/password + Google (нужно ли — уточню при настройке провайдера).
- Таблицы:
  - `profiles` (минимум: id, created_at) — авто-создаётся триггером.
  - `favorites` (user_id, product_id, product_snapshot jsonb, created_at) — синк избранного.
  - `price_history` (product_id, price, old_price, in_stock, captured_at) — снимок цен при каждом обновлении каталога.
  - `notifications` (user_id, product_id, kind: 'discount'|'stock', old_value, new_value, created_at, read_at).
  - `user_settings` (user_id, refresh_interval_minutes).
- RLS: каждый юзер видит только своё; `price_history` — public read.

### 3. Миграция локального избранного
При первом входе — переносим существующие записи из `localStorage` в `favorites` (по `product_url`), потом чистим локальное хранилище. До входа — избранное остаётся локальным и работает как раньше.

### 4. Страница товара: сравнение цен
На основе `price_history`:
- Показать текущую цену vs. предыдущую записанную (или средняя за 30 дней — выбираю «предыдущая», как более понятно).
- Разница в %, стрелка вверх/вниз, дата предыдущей цены.
- Мини-график sparkline последних 10 снимков.

### 5. Автообновление + уведомления
- Сервер-функция `refreshCatalog`: обходит каталог, пишет snapshot в `price_history`, сравнивает с последним снимком по каждому товару и создаёт `notifications` для юзеров, у которых он в избранном (новая скидка / появилось в наличии / пропало).
- Public HTTP-эндпоинт `/api/public/cron/refresh` (защищён секретом) — для внешнего пинга по расписанию. Плюс в UI: кнопка «Обновить сейчас» и селектор интервала (5/15/30/60 мин / вручную), который в фоне триггерит эту же функцию, пока вкладка открыта.
- Значок с числом непрочитанных уведомлений на вкладке «Избранное». Отдельная страница `/notifications` со списком изменений.

### 6. Улучшенная страница «Избранное»
- Сортировки: по дате добавления / по размеру скидки / по цене.
- Фильтр «только в наличии».
- Кнопка «Обновить выбранное» — перепроверяет цену/наличие конкретных карточек и пишет в `price_history`.
- Массовое действие: выделить всё / убрать выбранные.

### 7. Фикс сортировки каталога
Причина «то дешёвые сначала, то дорогие»: страницы каталога тянутся параллельно (`mapLimit`), дедупликация оставляет первое вхождение, порядок непредсказуем. Фикс:
- Сохраняю порядок страниц (page 1 → 2 → 3…), внутри страницы — исходный порядок с adishop.
- Дефолтная сортировка — стабильная «как на сайте», остальные сортировки (цена ↑/↓, скидка) — уже по кнопкам.
- Проверяю, что фильтр по полу не течёт (kids не попадают в man и т.п.) — категории уже разделены, но добавлю ассерт на URL товара.

### 8. PWA для iPhone (add to Home Screen)
- `public/manifest.webmanifest` с именем «Кроссы.by», `display: standalone`, `theme_color`, `background_color`.
- Иконки 180×180 (apple-touch-icon), 192, 512 (сгенерирую через imagegen).
- `<link rel="apple-touch-icon">`, `<meta name="apple-mobile-web-app-capable">`, `<meta name="apple-mobile-web-app-status-bar-style">` в `__root.tsx`.
- Без service worker (не нужен для «добавить на главный экран», не нужен офлайн).

## Порядок работ (один заход)
1. Включаю Cloud → мигрирую таблицы + RLS.
2. Auth страницы (`/auth`, `/_authenticated` gate только для настроек/уведомлений — каталог остаётся публичным).
3. URL-состояние каталога + фикс сортировки.
4. Server fn `refreshCatalog` + `price_history` + `notifications`.
5. Синк избранного (с миграцией из localStorage).
6. Обновлённая страница «Избранное» + страница «Уведомления».
7. Страница товара: блок сравнения цен + sparkline.
8. Настройки: интервал автообновления, вход/выход.
9. PWA-манифест + иконки.
